# 本地 3C 路线

在程序中运行“从地图记录 3C 路线”，将路线星标导出为有序 JSON 及配套地图截图。默认 `Nearest Beacon` 无需菱形：把目标星标组放在中央附近，记录器选取中央星标组并自动选择最近的可见信标作为入口。信标到首个星标只受录制半径限制，不受星标间最大距离限制，所以首段可能跨过障碍；请检查预览，必要时补途经星。该方式至少需要一个星标；`Diamond` 方式仍要求至少两个星标。

记录器提供初始顺序；请检查道路和障碍物，调整 JSON 中的点序，以及 `walk`、`combat`、`pickup` 动作。

录制后先查看同名 `.preview.png`：绿色 `S`/数字/连线为选定入口与纳入的星标顺序，红叉为排除的星标。可调小“相邻星标最大距离”和“录制范围半径”，避免把远处点或其他路线连进来。其他图标类型会忽略。默认开启“Capture Teleport Overview”：读取星标后逐步缩小地图，最多保存 6 张配准通过的 `.view-N.png`，主路线图和星标坐标保持不变。

书签路线会尝试在当前世界地图中定位同一独立地图、同一层的入口信标，再由信标图标和传送按钮双重确认后传送。可选填写旧版“Teleport Anchor”保留 Boss 图鉴方式；旧路线仍兼容。梦枢天罗等跨层路线本版不自动切层，`map_layer` 仅为预留字段。随后可在“路线队列”每行填一个 JSON 路径；留空则执行单条“路线文件”。`walk` 点之间持续移动，`combat` 和 `pickup` 点会停下处理动作。

迁移路线时请一起保留 JSON、`.map.png`、`.preview.png` 和全部 `.view-N.png`。自动缩放、视图搜索、信标及传送界面判断尚未通过实机验收，也不保证所有地图视野都能配准成功。这里不附带未经标定的成品路线。完整使用方法、格式和首版边界见[声骸刷取开发说明](../../docs/development/echo-farming.md)。
